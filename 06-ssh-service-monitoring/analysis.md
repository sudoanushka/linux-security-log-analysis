SSH Service Monitoring

Objective:

Verify the status of the SSH service on the Linux system and establish that the OpenSSH server is active before analyzing SSH authentication activity. 

Command Used:

sudo  systemctl status ssh

Service: 

The system uses the OpenSSH server to provide SSH remote-access functionality. 

The SSH service is managed through systemd and can be inspected using systemctl.

Analysis:

The SSH service status was reviewed using systemctl. 

The output confirmed that:
ssh.service - OpenBSD Secure Shell server
Active: active (running)

The service logs also showed that the SSH daemon (sshd) was listening for incoming connections on the standard SSH port: port 22

This confirmed that the SSH service was operational and capable of generating authentication events for subsequent security-log investigations.

Observation: 

The SSH service was successfully identified as active and running. 

The output provided useful information including-
- SSH service name
- Current service state
- Main process (sshd)
- Process ID information
- Service startup information
- Listening status
- SSH port (22)

Security Relevance:

SSH provides remote command-line access to Linux systems and is therefore an important service to monitor.

Security analysts should monitor SSH-related activity for events such as:
- Successful remote logins
- Failed authentication attempts
- Repeated password failures
- Unexpected user accounts
- Unusual source addresses
- Unexpected SSH service changes

An active SSH service is not itself evidence of malicious activity. However, authentication events generated by the service can provide valuable information during security investigations.

Finding:

- Service: OpenSSH Server
- Daemon: sshd
- Service Status: Active (running)
- Default Port: TCP/22
- Result: SSH service operational
- Security Assessment: Expected lab configuration

Key Learning: 

- Used systemctl to inspect a Linux security-relevant service.
- Verified that the OpenSSH server was running.
- Identified sshd as the SSH server process.
- Confirmed that SSH was listening on port 22.
- Learned why service status should be established before investigating authentication events.
- Prepared the environment for SSH log analysis.
